# Chrono-Surge

Retained Surgical Item detection — an offline visual second-check for the
surgical tray area, built on NVIDIA VSS + the Cosmos3 VLM.

Watches a fixed camera view of a tray/sterile field and flags a **HAZARD**
the moment an item enters the field and never comes back out — the actual
"never event" clinical risk (retained sponges, needles, instruments).

## Quick start

Prerequisites: Python 3.10+, `ffmpeg`/`ffprobe` on PATH, and an NVIDIA VSS
`base` profile deployment running locally (see below) for the two live
modes. The Mock Scenario mode needs neither.

```bash
git clone <this repo>
cd chrono-surge-dashboard
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

Open the printed local URL (default `http://localhost:8501`). If accessing
from another machine, use the host's LAN IP, not `localhost` — Streamlit
binds `0.0.0.0` by default so this works without any server change.

## Tech stack & architecture

- **Frontend/dashboard**: Streamlit (`app.py`), dark theme, custom
  DGX-style radial meters and stat tiles (no gauges/needles).
- **VLM**: `nvidia/cosmos3-nano-reasoner`, served locally via NVIDIA's
  [video-search-and-summarization (VSS)](https://github.com/NVIDIA-AI-Blueprints/video-search-and-summarization)
  blueprint's `base` profile:
  ```bash
  cd video-search-and-summarization
  deploy/docker/scripts/dev-profile.sh up --profile base --hardware-profile OTHER
  ```
  Reachable at `http://localhost:30082/v1/chat/completions` (OpenAI-compatible).
  No LLM is used — `nemotron-nano-9b-v2` (also in the `base` profile) is
  text-only and unused by this pipeline.
- **Video processing**: `ffmpeg`/`ffprobe` — window splitting, auto-compression
  to stay under the VLM's inline base64 size cap, duration probing.
- **Persistence**: plain JSON on disk (`session_store.py`), one folder per
  run under `analysis_runs/` — no database.

```
Video Input → ffmpeg (window + compress) → Cosmos3 VLM (structured JSON)
  → Guardrail Layer (name canonicalization + fragment rejection)
  → Ledger decay / continuity check → Dashboard + disk-persisted audit trail
```

Full design detail lives in `specs/`:
- `specs/system-design.md` — overall architecture, the three dashboard modes.
- `specs/inventory-guardrail-spec.md` — hallucination-fragment guardrails.
- `specs/live-inventory-decay-spec.md` — the presence-decay state machine
  and baseline-name-alignment rules.
- `specs/chronological-state-engine-spec.md` — the standalone per-frame
  zone-tracking pipeline (`vss_adapter.py` + `cse.py`, not wired into the
  dashboard — see Known limitations).

## Reproducing the demo

No API keys or `.env` file are needed — everything runs against the local
VSS deployment above. Three modes, selectable from the sidebar:

1. **Mock Scenario** — deterministic synthetic trace (`mock_engine.py`), no
   VLM call. Four gate-check scenarios (round-trip, occlusion, retention,
   endpoint-drop) validate the dashboard's alert logic in isolation.
2. **Upload Video (Live VSS)** — upload an `.mp4`/`.mov`/`.avi` of a tray
   area, click Analyze. One whole-clip VLM call, start-vs-end reconciliation.
3. **Live Analysis (10s windows)** — same upload, but analyzed in disjoint
   windows with running continuity checks, live token/latency telemetry, and
   a persisted transcript under `analysis_runs/<timestamp>_<filename>/`.

## Datasets / synthetic data

- **Mock Scenario mode**: fully synthetic, generated by `mock_engine.py`
  (`random.seed(7)`, deterministic) — no external data, built specifically
  to gate-check the dashboard UI before the real VLM pipeline existed.
- **Live modes**: any short `.mp4` of objects on a tray/table works as a
  test clip — developed and verified against short recorded test clips of a
  tray with everyday stand-in objects (pencils, gauze pack, ID card, etc.),
  not real surgical footage or any patient data.

## Known limitations & next steps

- VLM latency is ~30–90s per call regardless of clip length, which rules out
  true per-frame real-time analysis — this is why "Live Analysis" uses 10s
  windows rather than a live feed.
- Object naming is open-set (no fixed item vocabulary), which is more
  general but means very unusual VLM phrasing can still edge-case past the
  name-canonicalization guardrails — see `specs/inventory-guardrail-spec.md`
  and `specs/live-inventory-decay-spec.md` for what's already handled.
- No live RTSP camera input yet — file upload / simulated video only.
- A separate, more granular per-frame pipeline (`vss_adapter.py` + `cse.py`,
  zone-tracking with TRAY/HANDS/FIELD + debounced retention alerts) exists
  standalone but isn't wired into the dashboard — kept out to stay within
  VLM latency/GPU-memory budget for a live demo. See
  `specs/chronological-state-engine-spec.md`.
- All inference runs on local infrastructure (no cloud round-trip) — no PHI
  ever leaves the machine, but this also means the demo requires the VSS
  deployment to be running locally alongside the dashboard.
